# Нестационарный режим: исправления и доработки + новое окно ГУ

## Исправленные ошибки

### 1. Критический баг ядра: «нулевые» кадры анимации
**Симптом:** при числе снимков больше числа шагов (n_save > t_end/Δt + 1)
сохранялся только кадр t=0, остальные кадры оставались нулями — анимация
показывала «падение температуры в ноль» и полную бессмыслицу.
Например: t_end=600 с, Δt=60 с (10 шагов) при стандартных 50 снимках.

**Причина:** в `fem_core/api.cpp` массив моментов сохранения `save_at`
при округлении содержал дубликаты, а проверка `if` (вместо `while`)
«застревала» на первом дубликате и больше никогда не срабатывала.

**Исправление (двойное):**
- `fem_core/api.cpp` — `while` вместо `if` в `save_snapshot` (нужна
  пересборка fem_core.dll);
- `fem3d/core_bridge.py` — n_save заранее ограничивается числом
  шагов + 1. **Работает даже со старой, непересобранной DLL.**

### 2. Рост/падение температуры не виден в анимации
**Симптом:** тело на каждом кадре выглядит одинаково «полностью
раскрашенным» от синего к красному — динамики не видно.

**Причина:** цветовая шкала пересчитывалась на КАЖДОМ кадре по локальным
Tmin/Tmax этого кадра.

**Исправление:** `gui/viz3d.py` — новый API `set_fixed_clim()` /
`clear_fixed_clim()` (оба рендера: PyVista и Matplotlib). При
нестационарном расчёте шкала фиксируется по глобальному диапазону за всё
время → остывание реально «уходит в синий», нагрев — «в красный».
При стационарном расчёте шкала автоматически возвращается к авто-режиму.

## Новые параметры нестационарного режима (диалог «τ Нестационарный»)
- ρ и c_p прямо в диалоге (предзаполняются из задачи);
- скорость анимации (кадр/с) и зацикливание;
- чекбокс «Единая цветовая шкала для всех кадров» (вкл. по умолчанию);
- живая сводка: a = λ/(ρ·c_p), характерное время τ = L²/a, число шагов,
  число Фурье Fo — с предупреждениями (Δt > τ, t_end < τ/2, снимков
  больше шагов, слишком много шагов);
- кнопка «Подобрать Δt и t_end по τ» (Δt = τ/40, t_end = 4τ).

## Отдельный отчёт нестационарного режима
- Кнопка «Отчёт τ» на нижней панели (активна после нестационарного
  расчёта). Сохраняет:
  - `*.txt` — режим и схема, параметры интегрирования, теплофизика
    (a, τ, Fo с интерпретацией), ГУ, таблица динамики Tmin/Tmean/Tmax(t),
    анализ: характер процесса (нагрев/остывание), времена 63.2 % и 95 %
    изменения, темп процесса m (регулярный режим), степень выхода на
    стационар, T(t) в точках наблюдения;
  - `*_history.csv` — полная история: t; Tmin; Tmean; Tmax; T в точках
    наблюдения (для графиков в ВКР).
- Функции `export_transient_report`, `export_transient_history_csv`,
  `transient_summary` в `fem3d/postprocess.py`.

## Улучшения плеера анимации
- метка показывает t, номер кадра и Tmin/Tmean/Tmax текущего кадра;
- скорость берётся из параметров, поддерживается зацикливание;
- строка результата: «Tmean 100.00→82.56 °C (остывание)»;
- при стационарном расчёте плеер скрывается, шкала сбрасывается.

## Новое окно граничных условий
Вместо «простыни» (шаблоны + обдув + погружение + 6 карточек подряд):
- вкладка **«Грани»** — слева список 6 граней с живой сводкой условия
  («Y+ | конвекция: α = 123, T∞ = 25 °C»), справа редактор выбранной
  грани с формулой и подсказкой; сверху — шаблоны сценариев и кнопка
  «Применить ко всем граням»;
- вкладка **«Обдув»** — вынужденная конвекция (как раньше, но отдельно);
- вкладка **«Погружение»** — частичное погружение (как раньше, отдельно).
Клик по конкретной грани в главном окне открывает диалог сразу на ней.
Внешний API (result_bcs / air_flow_result / immersion_result) сохранён.

## Пересборка ядра на Windows (по желанию)
Питоновский кламп уже чинит баг со старой DLL. Для чистоты можно
пересобрать: в каталоге fem_core/build открыть fem_core.sln в Visual
Studio и собрать Release, либо:
    cd fem_core/build
    cmake --build . --config Release
и скопировать новую fem_core.dll на место старой.

# Дополнение: исправление цветовых тем (светлая / бежевая)

**Симптом:** при выборе светлой или бежевой темы оставались «тёмные пятна»
с нечитаемым текстом: панель результата на вкладке «Что будет, если…»,
вся вкладка «Графики», карточки в галерее «Выбор сценария нагрева»,
графики «Сравнение расчётов», окно справки, резервный 3D-вид (matplotlib).

**Причина:** в этих местах цвета фона и текста были прошиты константами
тёмной темы (#23262c, #2a2e36, #1f2228, #dcdee2 и т.п.) и не зависели
от выбранной палитры.

**Исправлено — все цвета берутся из текущей темы (current_theme()):**
- `gui/plots.py` — фигура, оси, легенды, подписи, гистограммы; добавлен
  `apply_theme()`, вкладка перекрашивается «вживую» при смене темы;
- `gui/whatif.py` — панель результата (фон input_bg + рамка темы),
  подсказка; добавлен `apply_theme()`;
- `gui/dialogs.py` — карточки галереи шаблонов (фон panel, рамка border,
  hover акцентом темы), окно справки, все приглушённые подсказки
  (17 мест) переведены на text_dim палитры;
- `gui/calculations.py` — оба графика сравнения расчётов и подписи;
- `gui/viz3d.py` (MatplotlibView) — фигура, оси, панели, тулбар,
  каркас; перекрашивается при смене темы через set_viewport_background;
- `main_gui.py` — apply_theme_to_widgets() теперь перекрашивает вкладки
  «Графики» и «Что будет, если…».

Диалоги (ГУ, нестационар, галерея) создаются заново при каждом открытии
и автоматически берут актуальную палитру.

**Проверки:** headless-тест переключения dark→light→sepia подтверждает,
что фоны фигур, панели результата и карточки галереи соответствуют
палитре; все 39 unit-тестов и полный GUI-смоук проходят.
