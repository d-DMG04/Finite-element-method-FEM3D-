# fem_heat3d — программный комплекс МКЭ для трёхмерной теплопроводности

Версия **1.2** — полнофункциональное GUI-приложение для решения стационарной
задачи теплопроводности

```
−∇·(λ ∇T) = Q   в Ω,
       T = T₀                  на Γ_D  (Дирихле),
−λ ∂T/∂n = q₀                  на Γ_N  (Нейман),
−λ ∂T/∂n = α(T − T∞)           на Γ_R  (Робен)
```

методом конечных элементов на линейных тетраэдрах P1.

## Архитектура

| Слой | Реализация | Назначение |
|------|------------|------------|
| Вычислительное ядро | C++17 + OpenMP, разделяемая библиотека `fem_core.{so,dll,dylib}` | сетка, сборка K и F, CG-решатель, потоки |
| Управляющий слой | Python 3.10+, NumPy, ctypes (пакет `fem3d`) | описание задачи, оркестрация, экспорт, верификация |
| Пользовательский интерфейс | PyQt5 + PyVistaQt (пакет `gui`) | вкладочный интерфейс, 3D-просмотр, picking |

## Возможности

### Геометрия
- Параметрический параллелепипед с настройкой размеров и плотности сетки
- Импорт из **MSH** (Gmsh), **VTU/VTK** (ParaView), **STL** (через gmsh-тетраэдризацию), **STEP/STP** (CAD-геометрия)
- 4 пресета: куб, тонкая пластина, длинная балка, микрокуб

### Физика
- Справочник из 12 материалов (серебро, медь, алюминий, латунь, стали, стекло, дерево, минвата, воздух и др.) или произвольный λ
- Объёмный источник по всему телу + локальные точечные источники + объёмные сферические подобласти
- Поузельные значения Дирихле (для импортированных данных от датчиков или верификации)

### Граничные условия
- Дирихле, Нейман, Робен на каждой из 6 граней (Box) или одной импортированной группе
- Шаблоны быстрой настройки: нагрев снизу + конвекция сверху, конвекция со всех сторон

### Решатель
- Метод сопряжённых градиентов (CG) с предобусловливателем Якоби
- Параллелизация через OpenMP (число потоков настраивается)
- Контроль точности и максимума итераций
- Диагностика: число итераций, норма невязки, время

### 3D-визуализация
- **Бэкенд PyVista** (рекомендуется): объёмный рендер, изоповерхности, сечения по любой оси, picking узлов с показом T в точке, размещение источников кликом мыши
- **Бэкенд matplotlib** (резервный): 3D-облако с цветом по T, сечения, базовый picking
- Стандартное управление: ЛКМ — вращение, СКМ/Shift+ЛКМ — панорамирование, колесо — масштабирование
- Кнопка «Сбросить вид»

### Вкладочный интерфейс
- **3D-вид** — модель и температурное поле
- **Графики** — гистограмма T, профиль T(·) вдоль оси, распределение |q|
- **Расчёты** — история всех расчётов сессии с возможностью переключения

### Меню
- **Файл**: импорт сетки, экспорт VTU/CSV/отчёта, выход (Ctrl+Q)
- **Вид**: сброс камеры (Home), режим picking узла, режим размещения источника
- **Источники**: добавить точечный/объёмный, очистить все
- **Настройки** (Ctrl+,): параметры CG, режим рендера, OMP-потоки
- **Справка** (F1): подробная справка и «О программе»

### Постобработка и экспорт
- Тепловые потоки q = −λ∇T (узловые)
- Экспорт VTU для ParaView, CSV (x,y,z,T,qx,qy,qz), текстовый отчёт

### Верификация
- 4 задачи T1–T4 (раздел 3.4 ПЗ):
  - T1: линейное решение T = x → ошибка ~10⁻¹²
  - T2: 1D-аналитика Дирихле + Робен → ошибка ~10⁻¹⁰
  - T3: **эмпирический порядок сходимости в L²** на гладкой гармонической функции → 1.64 → 1.85 → 1.93, среднее **1.89** (теория: 2.0)
  - T4: одновременно Дирихле + Нейман + Робен → ошибка ~10⁻¹⁰

### Тестирование
- **18 unit-тестов**, включая ядро, верификацию, локальные источники, импорт, поузельный Дирихле, экспорт

## Установка и сборка

### Системные требования

- C++17-совместимый компилятор (GCC ≥ 7, Clang ≥ 5, MSVC ≥ 2017)
- CMake ≥ 3.16
- Python 3.10+

На Ubuntu:
```bash
sudo apt install build-essential cmake python3 python3-pip
```

### Сборка C++ ядра

```bash
make build
```

Или вручную:
```bash
cd fem_core
mkdir build && cd build
cmake .. -DCMAKE_BUILD_TYPE=Release
cmake --build . -j
```

Под Windows (MSVC, исправлено в v1.1):
```bat
cd fem_core
mkdir build && cd build
cmake .. -G "Visual Studio 17 2022" -A x64
cmake --build . --config Release
```

### Python-зависимости

```bash
pip install -r requirements.txt
```

**Минимально достаточно** для запуска: `numpy`, `matplotlib`, `PyQt5`.

**Для лучшей 3D-визуализации** добавьте: `pyvista`, `pyvistaqt`, `vtk`.

**Для импорта STL/STEP**: дополнительно `gmsh`.

## Использование как библиотеки

```python
from fem3d import (CoreBridge, BC_DIRICHLET, BC_ROBIN, BC_NEUMANN,
                   FACE_Z_MINUS, FACE_Z_PLUS,
                   FACE_X_MINUS, FACE_X_PLUS, FACE_Y_MINUS, FACE_Y_PLUS)

with CoreBridge() as bridge:
    bridge.generate_box(0, 0.1, 0, 0.1, 0, 0.1, 20, 20, 20)
    bridge.set_material(lambda_=237.0, Q=0.0)         # алюминий
    bridge.set_bc(FACE_Z_MINUS, BC_DIRICHLET, T0=100.0)
    bridge.set_bc(FACE_Z_PLUS,  BC_ROBIN, alpha=25.0, T_inf=20.0)
    for f in (FACE_X_MINUS, FACE_X_PLUS, FACE_Y_MINUS, FACE_Y_PLUS):
        bridge.set_bc(f, BC_NEUMANN)
    bridge.add_point_source(node_idx=1234, power=10.0)
    bridge.add_volume_source_sphere(0.05, 0.05, 0.05, 0.01, 1.0e7)
    info = bridge.solve(tol=1e-8, max_iter=5000)
    T = bridge.get_temperature()
    flux = bridge.compute_fluxes()
```

## История версий

### v1.17 (текущая) — Полный аудит программы

Проведён сквозной аудит всех модулей (C-API, Python-обёртка, постпроцессинг,
batch, project, GUI). Математическое ядро было выверено ранее (v1.16) и
подтверждено. В этой ревизии найдены и исправлены два реальных бага.

**Баг 1 — радиация на сложных геометриях не линеаризовалась.**
Линеаризация радиационного ГУ (εσ(T⁴−T_env⁴) → эквивалентный α на каждой
итерации Пикара) работала только для box-геометрии. Для импортированных и
сложных сеток оценка температуры грани `_mean_T_on_face` не вычислялась,
поэтому α_rad замораживался на холодном приближении и радиационный теплоотвод
занижался. Метод `_mean_T_on_face` сделан универсальным (усреднение по узлам
граничных треугольников нужного face_id), ограничение `not has_external_mesh`
снято. Проверено: энергобаланс радиации на цилиндре 0.35% (было — не сходилось).

**Баг 2 — потеря данных при сохранении проекта.**
`save_project` не сохранял часть полей Problem, добавленных в v1.12–v1.14:
плотность ρ, теплоёмкость c_p, анизотропию (is_anisotropic, λ_x/y/z), имя
материала и точки наблюдения (термопары). При сохранении/загрузке проекта они
терялись. Теперь сохраняются и восстанавливаются все поля; добавлен
автоматический тест round-trip.

**Расширен gui_smoke_test.py** — добавлены сценарии «сохранение/загрузка
проекта» и «радиация на цилиндре», чтобы оба исправленных бага впредь
отлавливались автоматически (всего 8 сценариев на реальном PyVista).

**Замечания (ограничения, не баги):**
- `compute_nusselt` рассчитывается только для box-геометрии.
- Классификация граней сложных невыпуклых тел (тор, L-балка) по 6 face_id
  приблизительна — но ГУ применяется к группе граней корректно, а энергобаланс
  использует надёжную нормаль через тетраэдр.

**Проверки:**
- 29/29 unit + 4/4 верификация + 5/5 физика
- 8/8 сценариев GUI на реальном PyVista
- Энергобаланс: box, 15 геометрий, радиация — в пределах нормы

### v1.16

Проведён построчный аудит всей математической части. Само вычислительное
ядро (генерация сетки, сборка K и M, решатель PCG, восстановление потоков)
признано корректным и подтверждено численно:
- Формулы градиентов P1 точны до машинного эпсилона на 2000 случайных
  тетраэдров (ошибка ~3·10⁻¹², partition of unity Σ∇φ=0 ~10⁻¹⁶).
- Patch-тест: константное поле воспроизводится с ошибкой 10⁻¹³, линейное —
  в пределах точности решателя.
- Эмпирический порядок сходимости в L2 ≈ 1.89 (теория для P1: 2.0).
- Все 5 физических задач совпадают с аналитикой (поток через стенку,
  конвекция, источник, два материала, заданный поток).

Исправлены три расхождения между реальной сборкой `assemble()` и проверкой
`energy_balance()` (на сам расчёт T не влияли — только на диагностику):
1. **Box-объёмные источники** игнорировались в подсчёте генерации
   (учитывались только сферы) — теперь учитываются.
2. **Объёмный Q регионов материалов** не входил в генерацию — теперь входит.
3. **Дирихле-поток** для анизотропного материала считался по скалярному λ —
   теперь покомпонентно (q_i = −λ_i·∂T/∂x_i).

Генерация в энергобалансе теперь считается **поэлементно, в точности повторяя
логику C++ `assemble()`**, что гарантирует совпадение проверяемой генерации
с реально собранной правой частью. Результат: энергобаланс 0.00% на box и
всех 15 сложных геометриях, для глобального Q, box- и сфера-источников.
