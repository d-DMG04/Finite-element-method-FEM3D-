# fem_heat3d — программный комплекс МКЭ для трёхмерной теплопроводности

Полный программный комплекс численного решения стационарной задачи
теплопроводности

```
−∇·(λ ∇T) = Q   в Ω,
       T = T₀  на Γ_D,
−λ ∂T/∂n = q₀  на Γ_N,
−λ ∂T/∂n = α(T − T∞)  на Γ_R.
```

методом конечных элементов на линейных тетраэдрах P1.

Двухуровневая архитектура:

| Слой | Реализация | Назначение |
|------|------------|------------|
| Вычислительное ядро | C++17 + OpenMP, разделяемая библиотека `fem_core.so` | Сетка, сборка, решение CG, потоки |
| Управляющий слой | Python 3.10+, NumPy, ctypes (пакет `fem3d`) | Описание задачи, оркестрация, экспорт, верификация |
| Пользовательский интерфейс | PyQt5 (`main_gui.py`) | 4-зонное окно, цветовая карта, неблокирующий QThread |

## Возможности (v1.1)

- **Геометрия**: параметрический параллелепипед или импорт MSH-сеток (через meshio)
- **Материалы**: справочник из 12 материалов или произвольные λ, Q
- **Граничные условия**: Дирихле, Нейман, Робен на каждой из 6 граней; шаблоны быстрой настройки
- **Локальные источники тепла** (Ф2.4 ТЗ): точечные (P, Вт) и объёмные (Q₀ в шаре или коробке)
- **Поузельный профиль Дирихле** через `fem_set_node_dirichlet` — для верификации T3 и реальных датчиков температуры
- **Решатель**: CG с предобусловливателем Якоби, OpenMP-параллелизм, диагностика сходимости
- **Постобработка**: тепловые потоки q = −λ∇T, узловые карты, сечения по плоскостям
- **Экспорт**: VTU (ParaView), CSV, текстовый отчёт
- **GUI**: тёмная тема, 4 функциональные зоны, цветовая подсветка ГУ, неблокирующий расчёт в QThread
- **Верификация**: 4 задачи T1–T4 с эмпирическим порядком сходимости в L2 (показывает p≈1.9, теория 2.0)
- **Тесты**: 14 unit-тестов через `run_tests.py` или pytest

## Установка и сборка

### Системные требования

- C++17-совместимый компилятор: GCC ≥ 7, Clang ≥ 5 или MSVC ≥ 2017;
- CMake ≥ 3.16 и Make (или Ninja);
- OpenMP (входит в стандартный GCC/Clang/MSVC);
- Python 3.10+.

На Ubuntu 22.04 / 24.04:

```bash
sudo apt install build-essential cmake python3 python3-pip
```

### Сборка C++ ядра

```bash
make build
```

Это создаст файл `fem_core/fem_core.so` (Linux), `fem_core.dll` (Windows)
или `fem_core.dylib` (macOS).

Альтернатива — прямой вызов CMake:

```bash
cd fem_core
mkdir build && cd build
cmake .. -DCMAKE_BUILD_TYPE=Release
cmake --build . -j
```

На Windows (MSVC, Visual Studio):

```bat
cd fem_core
mkdir build && cd build
cmake .. -G "Visual Studio 17 2022" -A x64
cmake --build . --config Release
```

### Установка Python-зависимостей

```bash
pip install -r requirements.txt
```

## Использование как библиотеки

```python
from fem3d import (CoreBridge, BC_DIRICHLET, BC_ROBIN, BC_NEUMANN,
                   FACE_Z_MINUS, FACE_Z_PLUS,
                   FACE_X_MINUS, FACE_X_PLUS, FACE_Y_MINUS, FACE_Y_PLUS)

with CoreBridge() as bridge:
    bridge.generate_box(0, 0.1, 0, 0.1, 0, 0.1, 20, 20, 20)
    bridge.set_material(lambda_=237.0, Q=0.0)         # алюминий
    bridge.set_bc(FACE_Z_MINUS, BC_DIRICHLET, T0=100.0)
    bridge.set_bc(FACE_Z_PLUS,  BC_ROBIN, alpha=25.0, T_inf=20.0)
    for f in (FACE_X_MINUS, FACE_X_PLUS, FACE_Y_MINUS, FACE_Y_PLUS):
        bridge.set_bc(f, BC_NEUMANN)

    # Локальный источник в одном узле:
    bridge.add_point_source(node_idx=1234, power=10.0)
    # Объёмный источник в шаре:
    bridge.add_volume_source_sphere(0.05, 0.05, 0.05, 0.01, 1.0e7)

    info = bridge.solve(tol=1e-8, max_iter=5000)
    T = bridge.get_temperature()
    flux = bridge.compute_fluxes()
```

Высокоуровневый API через `Problem`:

```python
from fem3d import Problem, BoxGeometry, template_bottom_heat_top_cool, CoreBridge

problem = Problem(
    geometry=BoxGeometry(Lx=0.10, Ly=0.10, Lz=0.10, nx=20, ny=20, nz=20),
    lambda_=237.0,
    bcs=template_bottom_heat_top_cool(),
)
with CoreBridge() as bridge:
    problem.build_mesh_in_core(bridge)
    info = problem.solve(bridge)

from fem3d.postprocess import export_vtu, export_report
export_vtu(problem, "result.vtu")
export_report(problem, "report.txt")
```
