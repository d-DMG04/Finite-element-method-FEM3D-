# Добавления к программному комплексу МКЭ: обтекание потоком и нестационар

Документ описывает реализованные доработки: (1) конвективный теплообмен при
обтекании тела потоком воздуха со всеми сопутствующими величинами и (2)
исправление отображения нестационарной задачи.

---

## 1. Конвективный теплообмен при обтекании (вынужденная конвекция)

### 1.1. Физическая постановка

При обтекании нагретого тела потоком воздуха теплота отводится конвекцией.
Интенсивность теплоотдачи характеризуется **коэффициентом теплообмена**
`h`, Вт/(м²·К). Конвективный тепловой поток:

```
Q = h · A · (T_s − T∞),   Вт
```

где `A` — площадь поверхности, `T_s` — температура поверхности,
`T∞` — температура набегающего потока.

Коэффициент `h` заранее неизвестен — он зависит от скорости и направления
потока, свойств среды и формы тела. Его находят через **безразмерные числа
подобия**:

| Число | Формула | Смысл |
|-------|---------|-------|
| Рейнольдса | `Re = U·L / ν` | режим течения (ламинарный/турбулентный) |
| Прандтля | `Pr = ν / a = μ·c_p / λ` | свойство среды |
| Нуссельта | `Nu = h·L / λ_среды` | безразмерная теплоотдача |

Отсюда восстанавливается коэффициент теплообмена:

```
h = Nu · λ_среды / L
```

### 1.2. Цепочка расчёта (реализована в модуле `fem3d/convection.py`)

```
скорость U, направление  →  Re = U·L/ν
форма тела               →  Nu = f(Re, Pr)   (эмпирическая корреляция)
                         →  h  = Nu·λ_возд/L  (коэффициент теплообмена)
                         →  ГУ конвекции (α = h) на грани
                         →  расчёт МКЭ → поле T
                         →  Q = h·A·(T_s − T∞)  (конвективный поток)
```

### 1.3. Применённые корреляции для числа Нуссельта

- **Плоская пластина (продольное обтекание):**
  - ламинарный слой (`Re < 5·10⁵`): `Nu = 0.664·Re^0.5·Pr^(1/3)`;
  - смешанный/турбулентный: `Nu = (0.037·Re^0.8 − 871)·Pr^(1/3)`.
- **Цилиндр в поперечном потоке** — корреляция Черчилля–Бернстайна:
  `Nu = 0.3 + 0.62·Re^0.5·Pr^(1/3)/[1+(0.4/Pr)^(2/3)]^0.25 · [1+(Re/282000)^(5/8)]^(4/5)`.
- **Сфера** — корреляция Уитакера: `Nu = 2 + (0.4·Re^0.5 + 0.06·Re^(2/3))·Pr^0.4`.
- **Свободная конвекция** (для сравнения «без обдува») — вертикальная
  пластина, корреляция Черчилля–Чу через число Рэлея
  `Ra = g·β·ΔT·L³/(ν·a)`.

Свойства воздуха (ρ, ν, λ, Pr, c_p) берутся из таблицы Incropera
(Fundamentals of Heat and Mass Transfer, табл. A.4) при температуре плёнки
`T_film = (T_s + T∞)/2` с линейной интерполяцией.

### 1.4. Площадь поверхности фигур

Функция `surface_areas(problem)` вычисляет площадь поверхности по каждой
из 6 граней и суммарную:
- для параметрического параллелепипеда — аналитически
  `A = 2(L_x·L_y + L_y·L_z + L_x·L_z)`;
- для импортированной сетки — суммированием площадей граничных
  треугольников, сгруппированных по `face_id`.

Дополнительно `frontal_area(problem, direction)` даёт **фронтальную
(миделеву) площадь** — проекцию тела на плоскость, перпендикулярную потоку.

### 1.5. Направление и скорость потока

Скорость `U` (м/с) и направление (вектор или `+x/-z/...`) задаются
пользователем. По направлению грани классифицируются (через `cosθ = n̂·û`):
- **наветренная** (поток бьёт в грань), **боковая** (скользит вдоль),
  **подветренная** (в «тени»).

При желании коэффициент теплоотдачи можно распределить по обводу неравномерно
(опция `orient_weighting`: наветренная ×1.0, боковая ×0.7, подветренная ×0.5).

### 1.6. Использование

**Как библиотека:**
```python
from fem3d import Problem, BoxGeometry, CoreBridge, convection as cv

p = Problem(geometry=BoxGeometry(Lx=0.2, Ly=0.2, Lz=0.02), lambda_=237.0)
# Анализ обтекания (Re, Nu, h, Q, площади):
res = cv.analyze_forced_convection(p, speed=10.0, direction="+x",
                                   shape=cv.SHAPE_PLATE,
                                   T_inf=20.0, T_surface=80.0)
print(res.report_text())

# Назначить рассчитанный h как ГУ конвекции и решить:
cv.apply_forced_convection_bc(p, speed=10.0, direction="+x",
                              shape=cv.SHAPE_PLATE, T_inf=20.0, T_surface=80.0)
with CoreBridge() as b:
    p.build_mesh_in_core(b)
    p.solve(b)
```

**В GUI:** меню **«Обдув»** → «Конвекция при обтекании потоком…» (диалог
со скоростью, направлением, формой тела, T среды; кнопка «Рассчитать
(предпросмотр)» показывает Re/Nu/h/Q; галочка назначает h на грани).
Пункт «Площадь поверхности / число Нуссельта» показывает площади граней и
фактическое Nu после расчёта.

### 1.7. Проверка (верификация)

Демонстрация: `python3 demo_convection.py`. Контроль физической
согласованности (`tests/test_core.py::TestConvection`):
- свойства воздуха при 300 K совпадают с табличными (Pr≈0.707, λ≈0.0263);
- площадь поверхности box = `2(ab+bc+ac)` (машинная точность);
- `Nu` пластины совпадает с формулой `0.664·Re^0.5·Pr^(1/3)`;
- **замыкание**: заданный по корреляции `h` и восстановленный из поля T
  после расчёта МКЭ совпадают в пределах ~5 % (расхождение — известная
  погрешность восстановления потока у поверхности на элементах P1).

## 2. Исправление нестационарной задачи

### 2.1. Симптом

«Даже если задать начальную температуру тела, оно как будто не нагрето и
остывание не происходит».

### 2.2. Причина

Математическое ядро (неявная схема Эйлера `(M/Δt + K)·T^{n+1} = (M/Δt)·T^n + F`)
**работает корректно** — это подтверждено: нагретый куб корректно остывает
со 100 °C к температуре среды. Проблема была в **отображении** результата
в GUI:
1. после расчёта показывался **последний** кадр `T_history[-1]`, а при
   типичных параметрах (t_end = 3600 с, конвекция) тело к этому моменту уже
   практически остыло до температуры среды — отсюда впечатление «не нагрето»;
2. слайдер плеера тоже стоял на последнем кадре, и без ручной перемотки
   динамика остывания не была видна — отсюда «не остывает»;
3. в диалоге начальная температура по умолчанию была равна 20 °C —
   совпадала с температурой среды, и при конвекции `T∞ = 20 °C` действительно
   ничего не происходило.

### 2.3. Исправление

В `main_gui.py` и `gui/dialogs.py`:
- после расчёта показывается **начальный** кадр `T_history[0]` (нагретое
  состояние), слайдер ставится на 0;
- анимация остывания/прогрева **запускается автоматически**
  (`_autostart_transient_animation`);
- начальная температура по умолчанию в диалоге изменена на 100 °C с
  подсказкой, что она должна отличаться от температуры среды, чтобы была
  видна динамика.

Ядро (C++) **не изменялось** — менять там было нечего.
